# النسخة المكتبية على ويندوز (Windows desktop copy)

هذا المستند يشرح النسخة التي **تشغّل نفسها**: المستخدم يدوس على `erp_kayan.exe`
فتفتح نافذة البرنامج ويشتغل السيرفر معها، من غير أي ترمينال ولا أوامر ولا تنصيب
Node.js على جهاز المستخدم.

- التفاصيل الهندسية الكاملة: `docs/DESKTOP_WINDOWS.md` (هذا الملف).
- بناء النسخة: `scripts\build-desktop-windows.ps1`.
- فحص المشغّل تلقائيًا: `flutter pub run tools/desktop_check.dart`.

---

## 1. الشكل النهائي للنسخة

المجلد الذي يخرج من أمر البناء:

```
KAYAN-ERP\
  erp_kayan.exe                 البرنامج
  flutter_windows.dll
  data\                         الشاشات والترجمات
  backend\
    dist\src\main.js            سيرفر الـ API (ناتج nest build)
    node_modules\               مكتبات السيرفر (إنتاج فقط)
    prisma\                     مخطط قاعدة البيانات والترحيلات
    scripts\prepare-database.mjs  تجهيز قاعدة البيانات
    node\node.exe               محرّك Node اللي البرنامج بيشتغل بيه
    package.json
    .env.production.example     نموذج للإعدادات (بدون أي أسرار)
  README.txt                    ورقة تعليمات للمستخدم موجودة جوّه المجلد
```

لا يوجد داخل النسخة: `.env` الخاص بالتطوير، ولا أي مفتاح أو كلمة سر حقيقية.

### نواتج البناء الثلاثة

| الناتج | لمين | إزاي بيستخدم |
|---|---|---|
| `build\desktop\KAYAN-ERP\` | للتجربة والتشغيل المباشر | انسخ المجلد على أي جهاز وشغّل `erp_kayan.exe` |
| `build\desktop\KAYAN-ERP-windows.zip` | للنقل والتوزيع | فك الضغط في أي مكان وشغّل `erp_kayan.exe` |
| `build\desktop\KAYAN-ERP-Setup-1.0.0.exe` | **العميل النهائي** | دبل كليك → التالي → تم. البرنامج يظهر في قائمة «ابدأ» وعلى سطح المكتب |

ملف المثبّت بيتعمل بـ **Inno Setup 6** (مجاني، قياسي في الشغلانة دي، وما بيسيبش أي
مكوّن خلفه). سكربت البناء بيعمله **تلقائيًا** لو الأداة متسطّبة على جهاز البناء،
ولو مش موجودة بيتخطى الخطوة ويطلع المجلد والزبت كاملين زي ما هما.
ملف التعريف: `scripts\installer-windows.iss` — والمستخدم النهائي مالوش أي علاقة
بـ Inno Setup ولا بيشوف غير الملف الواحد.

### المثبّت بيعمل إيه بالظبط

- يحط البرنامج في `C:\Program Files\KAYAN ERP` (مجلد للقراءة فقط — لهذا كل
  بيانات التشغيل بتتكتب في `%APPDATA%`).
- يعمل اختصار في قائمة «ابدأ» + اختصار على سطح المكتب (اختياري).
- يشغّل البرنامج بعد التنصيب لو المستخدم طلب.
- إلغاء التنصيب نظيف: يمسح مجلد البرنامج، **ويسيب بيانات الشركة** في `%APPDATA%`
  عن قصد (مسحها = ضياع بيانات).

## 2. ما يحتاجه جهاز المستخدم

| المطلوب عند العميل | لماذا |
|---|---|
| PostgreSQL شغّالة (على نفس الجهاز، أو على جهاز في الشبكة) | البيانات محفوظة فيها |
| ويندوز 10/11 (64 بت) | لتشغيل البرنامج |
| صلاحية مدير **وقت التنصيب فقط** | للكتابة في `Program Files`. البرنامج نفسه بيشتغل بصلاحيات عادية |
| ~١٥٠ ميجا مساحة تقريبًا | البرنامج + السيرفر + محرّك Node المرفق |

**غير مطلوب:** Node.js، Flutter، Git، VS Code، ترمينال، أو أي أمر يدوي.
الاستثناء الوحيد: جهاز **البناء** يحتاج Flutter + Node (مرة واحدة).

قاعدة البيانات هي القرار **(أ): PostgreSQL على نفس الجهاز**، وليست مرفقة داخل
النسخة. النسخة تختبرها قبل التشغيل ولا تفترض أنها تعمل.

## 3. ما يحدث لحظة فتح البرنامج

1. النافذة تفتح وتعرض شاشة «جارٍ تشغيل البرنامج…».
2. البرنامج يبحث عن سيرفر KAYAN شغال بالفعل على المنافذ
   `3000, 3001, 3002, 3003, 3010, 3020`.
   - لو لقى واحد: يستخدمه (نسخة تانية مفتوحة، أو سيرفر تطوير) ولا يشغّل سيرفرًا ثانيًا.
3. غير كده: يختار أول منفذ فاضي، ويجهّز قاعدة البيانات
   (`prepare-database.mjs`: دور + قاعدة + `migrate deploy`، وكل خطوة تتكرر بأمان).
   ولو القاعدة فاضية تمامًا (مفيش ولا مستخدم) → شاشة «أول تشغيل» وإنشاء المدير،
   وبعد كده يكمل عادي (شوف 3.1).
4. يشغّل `node.exe dist\src\main.js` مع:
   `HOST=127.0.0.1` (الجهاز نفسه فقط)، `PORT` هو اللي اختاره، `NODE_ENV=production`،
   و `DATABASE_URL` من ملف إعدادات الجهاز.
5. يسأل `GET /api/v1/health` كل 300 مللي ثانية لحد 90 ثانية — **فحص صحة حقيقي،
   مش «استنى 5 ثواني»** — ولو العملية ماتت يقول السبب فورًا بدون انتظار.
6. أول ما الصحة ترد، البرنامج يبني شاشته الحقيقية على عنوان السيرفر ده.
7. لو فشل: تظهر شاشة عربية/إنجليزية بالسبب، مع مسار ملف السجل، وتلميح واضح
   لو المشكلة قاعدة بيانات (`DATABASE` / `P1001` / `ECONNREFUSED`)، وزر «حاول تاني».

## 3.1 أول تشغيل على جهاز جديد (قاعدة بيانات فاضية)

جهاز العميل عنده PostgreSQL فاضية تمامًا: البرنامج يعمل الدور وقاعدة البيانات
والجداول — لكن **مفيش أي مستخدم**. البرنامج ما بيخترعش حساب ولا بيستخدم كلمة سر
جاهزة: بيسأل اللي قاعد على الجهاز.

1. البرنامج يجهّز القاعدة، ولقي إن فيها صفر مستخدمين، فيقول في السجل
   `KAYAN-DB-STATE=empty` ويتوقف عن تشغيل السيرفر.
2. تظهر شاشة **«أول تشغيل على الجهاز ده»**: اسم المستخدم + كلمة السر + التأكيد
   (عربي/إنجليزي، شرط ٣ حروف للاسم و٨ لكلمة السر).
3. اللي بيدخل البيانات بيدوس «إنشاء الحساب والبدء» → البرنامج يعمل الشركة والفرع
   والأدوار والحسابات القياسية (٣٠ حسابًا) وأول مدير بكلمة السر اللي اختارها.
4. بعد كده البرنامج يبدأ عادي، والدخول باسم المستخدم ده وكلمة السر اللي اتكتبت.

**ليه كده:** النسخة فيها `prisma/seed.ts` القديم، وكان بيستخدم كلمة سر معروفة
(`admin`/`Admin@12345`) ومكتوب صراحة «Never run this against a production
database». فبدل ما نحقن كلمة سر معروفة في نسخة العملاء، البرنامج بياخد اسم
المستخدم وكلمة السر من اللي قاعد على الجهاز، بيمرّرهم لسكربت التجهيز **في
متغيّرات البيئة** (مش على سطر الأوامر، ومش بيتكتبوا في السجل)، والسكربت بينادي
نفس برنامج البذرة — يعني تعريف واحد لـ«شركة جديدة» في المشروع كله.

في التطوير: `npm run seed` زي ما هو بنفس القيم الافتراضية (`admin` /
`Admin@12345`) — ما اتغيرش حاجة.

## 4. إعدادات الجهاز وملف الأسرار

أول تشغيل يكتب — على الجهاز فقط — ملف:

```
%APPDATA%\KAYAN-ERP\kayan.env
```

فيه `DATABASE_URL`، و `ADMIN_DATABASE_URL`، ومفاتيح توقيع **متولّدة عشوائيًا**
(`JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET`، 48 بايت لكل واحد) — يعني كل جهاز
له مفاتيحه، ولا توجد أسرار تطوير داخل النسخة.

لو كلمة سر `postgres` على الجهاز مختلفة، أو قاعدة البيانات على جهاز تاني،
المستخدم يعدّل السطر ده ويقفل البرنامج ويفتحه تاني. الملف ده هو المكان الرسمي
لتعديل الإعدادات — لا يوجد أي إعداد مكتوب داخل الكود.

للدعم الفني فيه ثلاثة متغيّرات بيئة بتغيّر مكان الملفات بدون إعادة بناء:
`KAYAN_DESKTOP_BACKEND_DIR` (مجلد السيرفر)، `KAYAN_DESKTOP_NODE` (محرّك Node)،
و`KAYAN_DESKTOP_SETTINGS` (ملف الإعدادات).

السجل: `%APPDATA%\KAYAN-ERP\logs\backend.log` (سطور عادية بدون أكواد ألوان،
ويتجدّد لما يكبر عن 2 ميجا).

## 5. الإغلاق ودورة الحياة

| الحالة | النتيجة |
|---|---|
| المستخدم يقفل النافذة | البرنامج يوقف السيرفر (SIGTERM، وبعد 10 ثوانٍ SIGKILL لو ماستجابش) |
| البرنامج نفسه مات (Task Manager / انهيار) | job object في `windows/runner/main.cpp` بعلامة `KILL_ON_JOB_CLOSE` يقفل كل العمليات الابنة مع العملية الأم |
| نسخة تانية اتفتحت | تستعمل نفس السيرفر، وما تقفلوش عند الإغلاق لأنه مش بتاعها |
| نسخة التطوير (Flutter + `npm run start`) | لا تتأثر: التشغيل التلقائي لا يحدث إلا في نسخة `release` على سطح المكتب |

لا يوجد أي احتمال لسيرفر «يتيم» يفضل ماسك قاعدة البيانات بعد غلق البرنامج.

## 6. البناء والفحص

### 6.1 البناء على جهاز ويندوز

على جهاز ويندوز فيه Flutter و Node (ومثبّت Inno Setup 6 لو عايز ملف التنصيب):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build-desktop-windows.ps1
```

الناتج: `build\desktop\KAYAN-ERP\` و `build\desktop\KAYAN-ERP-windows.zip`،
و`build\desktop\KAYAN-ERP-Setup-1.0.0.exe` لو Inno Setup متثبت.

### 6.2 البناء من غير جهاز ويندوز (GitHub Actions)

`flutter build windows` محتاج ويندوز وأدوات Visual Studio، فمش ممكن على لينكس أو
ماك. عشان كده فيه خط بناء جاهز في المستودع:
`.github/workflows/windows-package.yml` — بيشتغل على جهاز ويندوز حقيقي
(`windows-latest`) بنفس السكربت بالظبط.

- **أي push على `main`** بيغيّر في `backend/` أو `lib/` أو `windows/` أو
  `scripts/` → الخط يبني ويفحص، والنواتج تتحفظ في تبويب **Actions** بتاع
  المستودع (Artifacts).
- **وسم إصدار** (tag) زي `v1.0.0` → نفس البناء، والنواتج تتنشر كـ**Release**
  ينزل منه أي حد من غير تسجيل دخول:
  `https://github.com/mohamedkamel78/ERP_KAYAN/releases`

إزاي تعمل إصدار جديد:

```powershell
git tag v1.0.1
git push origin v1.0.1
```

(غيّر `AppVersion` في `scripts\installer-windows.iss` الأول لو عايز رقم الإصدار
في اسم ملف التنصيب يتغيّر معاه.)

### 6.3 فحص نسخة مبنية قبل ما توصل للعميل

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify-package.ps1
```

مدقّق النسخة بيفحص المجلد نفسه — **من غير قاعدة بيانات ومن غير تشغيل** — ويجاوب
على الأسئلة اللي تحدد إذا كانت النسخة صالحة للتوزيع: كل الملفات موجودة؟ المحرّك
المرفق بيشتغل من مكانه؟ نقطة دخول السيرفر بتتحمل؟ فيه `.env` تطوير أو إعدادات أو
مستودع Git أو مسارات من جهاز اللي بنى النسخة؟ بيخرج بكود 1 لو فيه أي فشل، فممكن
يشتغل كخطوة في أي خط بناء.

اللي **مايقدرش** يفحصه (لأنه محتاج شاشة وقاعدة بيانات): سلوك البرنامج نفسه — إن
النافذة تفتح والسيرفر يشتغل والمستخدم يدخل. دول مغطّيين بـ`tools\desktop_check.dart`
و`tools\desktop_package_check.sh`.

## 8. ما لم يُنفّذ في هذه النسخة

- نسخة macOS و Linux: الكود مقسّم أصلًا لطبقة واحدة
  (`lib/core/backend/local_backend*.dart` بنفس أسلوب
  `lib/core/platform/browser_actions.dart`)، وما ينقص هو بناء
  `flutter build macos/linux` وسكربتات تغليف مثل سكربت ويندوز.
- توقيع الكود (code signing): النسخة غير موقّعة، فويندوز قد يعرض تحذير SmartScreen.
- المُثبّت: ملف التعريف `scripts/installer-windows.iss` جاهز ومربوط بسكربت البناء (الخطوة 7/7)، لكن تجميعه نفسه بيتم على ويندوز بـ Inno Setup 6، فالناتج المجرب هنا هو المجلد والـzip. مفيش `.msi`.
- لو حد شغّل برنامج على جهاز مش عليه PostgreSQL: لا توجد قاعدة مرفقة (قرار أ).
